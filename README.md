# Happy GitHub Journey

把项目与文章拆成关键设计、技术与原理的静态学习站。当前先收录素材链接并标记待解析，具体解析粒度需要真实样例校准；最佳实践输出仍在规划中。

- 网站：[happy-github.anjing.cc](https://happy-github.anjing.cc/)
- 公开仓库：[anjing-le/happy-github-journey](https://github.com/anjing-le/happy-github-journey)
- 之前的结构预览保存在 Git 历史中。

## 本地构建

需要 Node.js 18 或更新版本。无第三方依赖。

```bash
npm run build
```

站点源码在 `site/`，内容权威在 `content/` 的 Markdown。构建先校验资料与关联，再复制界面源码并生成 `dist/catalog.js` 和 `dist/catalog.json`，为样式、脚本与内容依赖添加内容哈希版本。界面使用原生 HTML、CSS 和 JavaScript，无第三方运行时依赖；勿手改生成文件。

## 收录与学习

- 2026-10-02 收到 15 个微信图文链接，去重后保存 14 条，均为“待解析、待存档”。标题暂用收录序号，未取得原文时不猜测内容；第一篇访问返回微信环境验证页，其他篇尚未检查。
- “待解析”表示尚未拆解，“待校准”表示 AI 初稿，“已认可”表示用户认可本条内容。收录、取得原件和解析是独立状态。
- 来源链接保留在第一层；未来解析结果分别放进 `content/designs/` 与 `content/technologies/`。只维护来源→设计、设计→技术的关联，出处与反向关系由构建生成。
- 原始 PDF、截图等保存到 `.pocket/<source-id>/`，该目录不进入公开 Git 或网站；记录捕获日期、完整性和缺失项。PDF 是快照，动图、视频和外链可能缺失。本地保存不代表已经有异地备份。
- 新增或修改原件后运行 `npm run verify:archives` 核对本地文件；公开构建只验证存档记录，Cloudflare 不依赖这台机器上的私有 PDF。
- 项目 Skill 在 [skills/happy-github-journey/SKILL.md](skills/happy-github-journey/SKILL.md)，内容格式在其引用文件中。目前为待真实样例校准的初稿：先收录，再用一条完整素材调整粒度，认可后批量处理指定的待解析项。
