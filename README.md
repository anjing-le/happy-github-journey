# Happy GitHub Journey

围绕问题与目标，把项目与文章吸收为整体理解、可组合的方法和基础概念的静态学习站。当前用首篇 PDF 打磨三层初稿与 Skill，表达粒度仍待用户校准；最佳实践入口已预留，输出内容仍待打磨。

- 网站：[happy-github.anjing.cc](https://happy-github.anjing.cc/)
- 公开仓库：[anjing-le/happy-github-journey](https://github.com/anjing-le/happy-github-journey)
- 之前的结构预览保存在 Git 历史中。

## 本地构建

需要 Node.js 18 或更新版本。无第三方依赖。

```bash
npm run build
```

站点源码在 `site/`，内容权威在 `content/` 的 Markdown。构建先校验资料与关联，再复制界面源码并生成不含正文的 `dist/catalog.js`、`dist/catalog.json`，正文分别写入 `dist/details/<内容哈希>.json`，通过目录中的 `bodyUrl` 关联。样式、脚本与内容依赖使用内容哈希版本。界面使用原生 HTML、CSS 和 JavaScript，无第三方运行时依赖；勿手改生成文件。

运行 `npm test` 会先构建，再检查正文拆分与加载、缓存与失败重试，以及多来源筛选和关系选择的回归用例。

## 图文存档工具

Skill 自带 Python 工具，支持公开微信 URL、经核实的公开转载页和已有网页 HTML 导入，流程见 [图文获取与存档](skills/anjing-happy-github-journey/references/wechat-capture.md)。它保存实际取得的 HTML、正文、离线阅读文件、图片和校验清单；遇验证页返回失败，有图片缺失则记录缺失，不修改解析状态或自动宣称完整。

用户提供 PDF 或截图时优先使用该原件。只有链接时，可查找原作者同步版或明确列出原出处的公开转载；搜索引擎缺少结果时可补充公开站内搜索。已有正常取得的网页也可导入；工具的 Python 依赖不进入静态网站。

## 按需加载与扩展

- 首次进入只读取轻目录；打开详情或复制时才请求该条正文。共享同一条的请求，成功后在当前页面缓存；失败不污染缓存，15 秒超时后可重试。较旧页面若遇已更新的正文地址，可以刷新获取新目录。
- 详情立即打开标题和摘要，正文显示加载态；关闭、切换或重新打开时，通过请求版本保护当前阅读内容。失败提供重试和刷新入口。冷缓存复制通过 `ClipboardItem` 的 Promise 保留用户点击授权；不支持时先准备正文，再提示用户点击复制。
- 固定关系快照缓存，反向关系和搜索索引预计算；逐卡关系判断使用 Set，连线使用节点索引，每张卡片的位置在每次绘制中只测量一次。关联置顶、悬停预览、键盘顺序和手机学习路径沿用当前交互。
- 已用现有素材在浏览器核对首屏无正文请求、首次及缓存复制、失败重试、慢请求切换与关闭重开；320px、393px 布局已核对。9 项回归测试覆盖正文无损拆分、并发缓存、超时重试，以及多来源和扩展类型筛选。后续随真实素材规模增长测量加载与交互表现；当前检查不代表千级数据或手机真机验收。
