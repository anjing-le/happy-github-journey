# 安静の GitHub Journey

通过学习优秀文章和开源项目，帮助用户积累见识、设计思路和判断依据。随着 AI 的实现能力增强，用户能够更清楚地提出目标、指引方向、判断取舍，并与 AI 一起形成合适的方案。

降低阅读负担，同时保留关键因果：理解一个设计为什么成立，遇到类似问题能想起值得借鉴的实践，看见技术名词能理解其用途。未来根据新场景的目标和约束，选择、调整、组合这些积累，形成自己的设计判断，再交给 AI 推演、实现和验证。积累数量本身不代表能力提升，文字必须帮助建立“什么情况下应该想到它”的联系。

## 用途介绍与自我介绍

先判断是否为介绍请求。当用户问本 Skill“是干啥的”“有什么用”，或在明确指向本 Skill 的上下文中要求“介绍一下自己”时，读取 [固定介绍](references/introduction.md)，将其中的完整正文直接作为回答，保留措辞、段落、三层列表与加粗格式，不再另行概括或改写。除非用户当次明确要求缩短或调整，否则不删减，也不追加项目进度、技术操作清单或任务建议。

纯介绍请求到此结束，不进入下面的收录、解析或发布流程，也不必读取仓库和存档。用户同时提出其他具体问题时，先给出固定介绍，再回答额外问题。普通的助手自我介绍若未指向本 Skill，不套用这段文字。

## 定位与当前阶段

先读目标仓库的 `AGENTS.md`、`README.md`，写内容时读 [内容格式](references/content-format.md)。优先使用用户指定的仓库；本 Skill 随仓库保存，仓库副本的根目录是本 Skill 目录的上两级。通过本机符号链接调用时先解析真实路径；复制安装时不能凭该相对路径定位项目。

用户已确认本项目的目的，以及“项目与文章 → 领域实践 → 技术与概念”的三层规则。2026-10-30 已明确授权处理本批 23 个去重文章链接、指定的开源项目及少量互补项目，并要求多智能体并行分析、分批推送上线；这取代此前仅校准首篇的范围限制。首篇继续保留，新增内容均为待校准初稿，组织规则确认不等于每条内容已经认可。后续按当次用户指定或授权选择的范围处理，不自动恢复旧列表或无限扩展候选。

## 收录、存档与状态

- 用户提供 PDF 或连续截图时，优先使用本次原件：保存后核对页数、首尾、正文与图示，渲染 PDF 并逐页阅读，扫描件按需 OCR。文字抽取成功不代表图示已读到；有截断、缺图或顺序不明时记录缺失，不能猜补。来源链接从用户提供的信息或原件中核实。
- 只有链接、需要获取微信图文时读 [图文获取与存档](references/wechat-capture.md)：主动获取正文与图片；原链接不可读时，查找原作者同步版或可核实原链接的公开转载，再自动存档。已有网页原件也可导入。浏览器连接、网站访问和内容完整性分别核对。
- 收录用户给出的材料；用户授权选题时，选择数量有边界、设计互补的材料。Star 只能帮助发现项目，不能证明设计优良或生产成熟。新链接进入“项目与文章”，保存原始 URL、来源类型、接收日期与备注，标为 `pending`（待解析）；类型允许扩展。
- 相同链接检查是否已有条目，合并备注并保留原内容。标题能核实才填写；无法读取时使用明确的暂定标签并解释，不根据链接猜正文。
- 不同链接也可能对应同一文章的不同发布版：核对实际差异，保留来源入口，共用含义与条件一致的下层条目。开源仓库重定向时核对新归属，内部记录旧地址、实际地址和读取的 commit SHA。
- 原始来源链接与原件同时保留。PDF 是内容快照，动图、视频和外链可能缺失；记录捕获日期、完整性和缺失项，不能把 HTTP 200、验证码页、标题或部分图片当作取得完整文章。
- 公开转载可以作为有来源依据的学习材料，保留原始链接、转载地址和实际取得的版本；核实正文中的原链接及图示，不把转载快照称为微信原件。未对照原文时，一致性仍未核验。
- 本地原件存档后运行 `npm run verify:archives` 核对真实文件。公开部署仅验证存档记录的格式，无法检查这台机器上的私有原件；本地保存也不代表已经完成异地备份。
- 完整 PDF、截图或网页原件放在 `.pocket/<source-id>/`，保持原件格式并在条目中关联；该目录不进入公开 Git 与网站。只有确实取得文章原件才标记“存档已保存”，验证页和失败报告不属于文章存档；实际核对正文和图片后才能标记完整性已核对。文件未取得时保持“待存档”。
- 收录、存档与解析是独立状态。单条 AI 解析后为 `draft`（待校准）；用户明确认可本条内容后为 `reviewed`（已认可）。认可 Skill 不等于认可每一条输出，批量结果默认仍是 `draft`。

## 知识组织与粒度

**项目与文章**：用精简、通俗的文字吸收整体：什么背景、出于什么目的、为什么这样设计、几个关键安排怎样配合，以及关键取舍。保留原名称，正文默认“问题与目标、方案怎么做、适用条件与取舍”。读者不用通读原件，也能复述整体设计思路；压缩阅读负担时保留关键因果与必要例子，不把解释全部拆给下层，不逐章复刻摘要。悬停默认“问题、目标”。概念介绍或综述按实际表达，不编造问题。

**领域实践**：有依据、值得在某类问题下再次采用的相对完整解法。标题保留可识别的领域和做法，正文讲清解决哪类问题、怎样做、为什么有效、适用条件和代价，帮助读者遇到类似问题时想到并选择它。先判断三个要点：能否明确描述反复出现的问题；是否有具体安排和作用原因；是否能说清采用条件和取舍。仅有一个动作、功能名、依赖或文章步骤清单时，留在第一层；有成熟做法时可以提炼，也可以关联已有实践或完全不建卡。领域内可复用即可，不强求跨行业通用。称为“最佳”必须说明成立条件，不虚构亲测效果。悬停用“问题、做法”。

**技术与概念**：补齐理解方案、参与讨论需要的技术常识。选择第一、二层中值得独立认识的框架、技术、机制或概念，用自然短段落讲清“是什么、能干什么”，必要时补一个小例子或易混淆的区别，不显示固定小标题。深度以能用自己的话解释、知道在方案中承担什么作用为准；先解释必要术语，不用一串陌生词定义另一个陌生词，不递归拆出所有新名词或默认深入源码。调优步骤与具体方案条件由上层承接。悬停“是什么、能干什么”。

把两个决定分开：**是否独立成卡**，看它能否承担独立的学习、检索或复用需求；**卡内讲多深**，看当前理解与判断需要。不能因为某个词有定义就建卡，也不能为了缩短正文而丢掉关键解释。篇幅和卡片数量不设配额，详见 [内容格式与粒度示例](references/content-format.md)。

先吸收整体，再检查已有方法与概念是否足够；只有出现独立且有用的新知识单元时才新建。相同名称不必然同义，合并或复用要检查含义和条件。通用卡保留可迁移的解释，场景如何组合由第一层说明。单篇允许没有新增方法或概念，避免为了填满三列而拆分。

复用领域实践时检查其全部下层关系：方法只关联理解该方法确实需要的概念，某一来源特有的框架和实现技术直接挂回该来源。避免复用通用方法后，把另一篇没有用到的技术也传递到关系图中。

来源和未来自己的最佳实践共用下层知识库：顶层通过 `designs` 引用领域实践，领域实践通过 `technologies` 引用概念；顶层也可直接引用技术，无需硬造中间层。数据目录与字段沿用 `designs`。未来的顶层输出围绕具体新场景，说明为什么选择、调整和组合这些实践，检查组合之间的条件是否冲突，并记录真实验证结果。普通收录不自动生成顶层最佳实践。

完成草稿后自查：第一层能否让人复述设计思路，第二层能否让人遇到类似问题时想到它，第三层能否让人听懂并参与讨论。检查实际文字，不以标题齐全或卡片数量代替吸收质量；不要给每张卡附加一套学习口号或问答作业。

## 吸收、证据与校准

- 项目核对 README、核心源码与配置，文章完整阅读正文和图示。内部按材料检查重要动机、推导、例子与取舍是否被吸收；公开表达按理解与复用重新组织，不按原件章节复制结构。材料不足时保持待解析，不能补造知识。
- 项目按同一 commit 读取 README、架构说明与关键执行路径，保存本次选读文件及清单；选读快照不冒充完整仓库镜像，完整性可标 `partial` 并在内部说明范围。不需要为分析项目安装、启动其依赖或执行其脚本。营销效果、推测的闭源内部结构和未来路线图不能写成已验证实现。
- 在 `.pocket/<source-id>/evidence.md` 记录实际使用的版本、原件完整性范围、关联条目 ID、章节或页码、源码位置，以及事实、推断和未验证项；粒度调整时简记保留、合并和正文承接的理由，防止压缩后丢失关键内容。这些记录不进入公开 catalog、详情或复制内容。
- 公开详情直接讲知识，不出现“原文、作者、PDF 页码、引用”等来源叙述和证据段落。重要适用条件用自然知识语言写进相关解释；只在它影响理解或使用时说明，不为每卡附加审计说明。
- 实现存在不代表效果已验证。涉及可执行配置时，核对版本、受支持取值与实际执行路径，核对过程留在内部笔记；公开内容保留有依据的做法与条件，不把不确定主张写成事实，也不虚构亲测经验。
- `summary` 和悬停要素帮助快速理解，详情承载必要解释，三者不维护成重复的长短两套文章。不设固定字数或条数；以“整体读得懂、关键因果不丢、方法值得复用、概念足够支持判断”为校准标准。
- 按用户反馈修正本篇并同步调整 Skill，替换冲突规则，避免不断叠加要求。单次修正不自动成为已认可样例；是否形成通用粒度、是否批量处理仍由用户明确认可。

## 完成一次任务

按实际授权范围保存、构建与发布，遵守仓库规定的提交身份。已有网站发布授权适用于本项目的收录展示，不扩大为公开原件或自动生成最佳实践。批量逐条保留成功、证据不足和访问失败结果；已完成且引用完整的一批可以先构建、推送、核对上线，不能把“已写文件”说成用户已经能看到。最佳实践入口已预留，内容存于 `content/practices/`，具体格式见内容格式。它围绕场景和目标组合已有设计与原理，普通素材拆解不自动生成最佳实践文章，未验证的结果不得写成实践成果。

用户要求并行时按素材分组，给各智能体分配独立文件与 ID，先共享已有知识目录。主智能体统一复核事实、粒度、重复概念和关系，再构建发布；不能让多个智能体同时改同一条目或各自推送。并行提高处理速度，不降低逐条阅读和来源核对标准。

简短交代收录了什么、哪些已经存档或解析、哪些仍缺材料。分别核对文件保存、构建、提交推送、部署和可见效果，不用其中一个代替其他状态。
