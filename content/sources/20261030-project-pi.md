## 问题与目标

编程助手既需要调用模型和工具，也要处理持续对话、历史恢复与用户中途调整。Pi 把这些能力拆成可以独立使用的部件，使开发者能够使用完整命令行助手，也能把 Agent 运行能力嵌进自己的产品。

## 方案怎么做

底层模型 API 统一不同供应商的消息与流式输出，Agent 循环负责调用模型、执行工具并把真实结果接回下一轮。交互界面、SDK 和 RPC 位于其上，使同一运行基础能被终端用户或其他程序使用。中途指引与结束后的追加任务进入不同队列，既能改变当前方向，也能接续后续工作。

个性化能力通过 TypeScript 扩展、Skill、提示词模板和主题接入。扩展可注册工具、监听事件或调整上下文；基础运行层不必为每种团队流程内置一套固定方案。

会话以追加日志保存，并通过父子关系形成分支。回到旧节点换个方向时，原尝试仍然保留；当前模型输入沿所选路径构建，较早内容可以用摘要压缩。例如先尝试一种修复，再返回分叉点尝试另一种，不必把全部探索混成一条历史。

## 适用条件与取舍

适合需要定制工作流或构建自己的 Agent 产品的人。可扩展意味着也要自行承担配置、扩展兼容和权限边界；扩展在同一进程中运行，不能把工具拦截当作操作系统级隔离。会话分支只改变对话路径，已经修改的文件与外部动作不会因此自动回退。
