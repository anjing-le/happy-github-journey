## 问题与目标

编程 Agent 不只是一次模型请求。它需要接收用户的新要求、执行工具、显示过程、管理权限，并在上下文变长后继续工作。可靠性来自这些环节的配合，而不是只把提示词写得更长。

## 方案怎么做

运行时把用户操作和执行事件分开：客户端提出开始、继续或中断，核心执行层管理任务，再把进度与结果传回。App Server 提供协议接口，让不同客户端复用这些能力。模型请求、工具执行和继续推理形成内层循环；能并行的工具可以减少等待，但有依赖或副作用的操作仍需保持正确次序。

环境信息按当前状态组织，稳定部分尽量复用，变化部分明确更新。多 Agent 协作把任务分给独立上下文，再通过消息和产物交接；它减少单个窗口的负担，却仍需要处理依赖和冲突。

长任务有两种值得区分的接续思路：压缩历史，留下目标、决定和未完成事项；或启动新窗口，依靠任务笔记、历史与持久产物按需回读。长期记忆则承担跨任务的经验提取和整理，不能与这次任务的进度混为一谈。Codex 存在多条相关实现路径，具体启用方式取决于版本与配置。

## 适用条件与取舍

可借鉴的是职责分离、状态保存和可回读交接。摘要会遗漏细节，长期记忆也会过期，所以重要决策需保留依据。并行、压缩与记忆都增加工程复杂度，应围绕真实的长任务瓶颈采用，不把某个版本的阈值或内部接口当成通用规则。
