## 问题与目标

把知识页面做成可拖动的块，看起来只是界面变化，实际涉及内容身份、嵌套、格式、选区和协作。若只保存一段 HTML，再用位置拼接修改，很容易在内容移动后改错对象，也难以持续引用同一个块。

BlockNote 在富文本编辑基础上提供块式文档与 React 交互。它把段落、列表、图片和其他内容组织成结构化块，让产品可以围绕块编辑与扩展，而不是从头处理所有底层编辑行为。

## 方案怎么做

每个块具有 ID、类型、属性、内容和可选子块。ID 在块的生命周期里保持稳定，移动位置不应改变身份；类型与属性说明它是什么，子块表达嵌套关系。文字内部的样式与链接则作为内联内容处理，表格还有自己的结构。

统一结构使编辑器能够判断哪些内容有效，也便于保存、导入导出与自定义块。例如知识卡片可以增加特定属性和渲染方式，但格式规则需要与读写逻辑一起设计，不能只新增一个视觉组件就认为数据兼容已经完成。

批量替换块时，输入先转换为文档节点并校验，再在编辑事务中处理删除和插入。前面一次修改会改变后面的位置，因此需要通过事务的位置映射继续定位。稳定 ID 用于找对象，位置映射用于完成这次编辑，两者解决不同问题。

多人协作借助 Yjs 共享文档来交换并合并更新，并通过协作配置接入网络传输。文档结构、编辑器和共享数据需要配套，参与者使用不兼容的格式或扩展，仍会给协作带来问题。

协作更新能够收敛，不代表业务内容一定合理，也不等于已经有保存、备份和权限管理。接入哪种传输服务、谁能进入房间、数据保存在哪里以及断线后如何恢复，需要产品自己选定；演示用公共房间不能直接当成企业知识空间。

## 适用条件与取舍

适合笔记、知识库或需要块式编辑的产品。若只是只读的静态内容展示，直接引入整套编辑器可能增加不必要的体积与状态复杂度；可以先借鉴稳定块身份与结构约束，再判断是否需要在线编辑。

BlockNote 基于 ProseMirror 等编辑基础，核心采用 MPL-2.0，XL 扩展采用 GPL-3.0 或商业许可，使用时要区分具体包。块格式、扩展与协作数据也构成长久维护的接口，需要考虑历史内容迁移，而不只是当前界面能否编辑。
