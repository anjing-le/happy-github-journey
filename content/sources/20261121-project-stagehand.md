## 问题与目标

网页改版后，写死的选择器可能失效；但每次点击都让模型从头推理，又会增加费用和不确定性。遇到登录、翻页、嵌套页面与数据抽取，脚本和模型需要各自承担擅长的部分。

Stagehand 给可编程浏览器增加语义操作：观察页面找到目标，按自然语言执行一步，或按指定结构提取内容。流程仍可以由程序组织，模型主要处理界面表达变化和内容理解，目标是让自动化既灵活，又能被检查。

## 方案怎么做

观察阶段读取当前页面的可访问性结构，把按钮名称、角色和状态等信息整理给模型。模型返回页面对象标识，再映射为实际可定位的元素；程序随后进行点击、填写或拖动。定位不应依靠模型虚构页面中不存在的路径，页面变了也需要重新观察。

observe 用来找目标而不直接操作，act 执行具体动作，extract 按字段结构取数据。它们可以与普通定位器代码混用。例如先让模型找到邮箱和密码输入框，再由程序填入凭据，之后抽取发票的编号、金额和付款状态。这样减少直接把敏感值放进自然语言指令的需要，但仍要核对页面后续快照与数据流是否会包含这些值。

当前 v4 结构把浏览器驱动与语义服务放到靠近浏览器的扩展侧，SDK 通过共同协议调用。协议定义集中维护，多语言客户端围绕相同契约工作；运行时兼容性按协议版本判断，不能只看 SDK 与扩展包的版本数字是否一样。

抽取前先定义所需字段，再从实际已加载的页面范围读取。页面里出现链接时，可以借助页面对象到真实 URL 的映射恢复地址，减少凭空补写的机会。返回 JSON 合法，只证明结构可用；字段是否抄对、列表是否读全，仍需要结合原页面检查，分页和懒加载也要实际推进。

重复调用可以考虑缓存，但复用条件必须包含指令和页面内容等上下文。当前托管缓存依赖 Browserbase 项目与会话，本地浏览器不是打开同一个开关就拥有相同服务；个性化内容、敏感数据和视觉抽取还有额外限制。缓存动作失效可以回到推理流程，但重试前仍要确认是否已经产生提交等外部影响。

## 适用条件与取舍

适合网站内容采集、后台录入和固定业务步骤中的模糊定位。登录会话可以持久保留，但过期、网站验证和访问限制仍是独立问题；工具不能保证任意网站都可读取，也不能用一次成功定位证明整篇图文已经完整取得。

模型调用、浏览器状态与网站变化都会影响可靠性。建议把访问、页面就绪、动作执行和业务结果分别核对；本地与托管运行的数据边界、依赖和计费也分别判断。需要自主决策的复杂任务可以在上层组织，单个浏览器动作成功并不代表整项任务已经完成。
