## 什么时候用

Agent 频繁修改代码，团队需要在代码进入共享仓库前发现遗漏、规范问题和明显缺陷。

## 怎样做与取舍

从已确认的需求和方案列出行为变化，包括正常结果、异常和回归影响；为重要变化确定测试或其他可复核证据。先让测试表达期待行为，再实现修改，避免只为现有代码补一份必然通过的检查。

推送前检查变化与证据是否对应，运行测试、静态扫描和内部评审。可以用 Git 推送前钩子承接这些步骤，失败时阻止普通推送路径继续推进，结果与对应变更一起保留。

钩子只约束启用它的本地路径，不能替代共享仓库的持续检查；静态扫描也无法证明业务正确。真实环境接口、部署和业务验收仍需分别验证，测试不要机械重复实现。
